경력 요약

메디플러스솔루션에서 2024년 5월부터 Android 개발자로 근무하며 신규 헬스케어 서비스 개발과 기존 건강관리·재활·명상 앱의 유지보수 및 기능 고도화를 담당했습니다. Kotlin 기반 Android 앱에서 Jetpack Compose와 기존 Android 화면 구조를 함께 다뤘으며, WebView 하이브리드 기능, BLE 의료기기, 헬스 데이터, Media3, CameraX와 TensorFlow Lite, 인앱 결제, 보안 대응, CI/CD 등 서비스 운영에 필요한 기능을 개발했습니다. 단순히 기능을 구현하는 데 그치지 않고 운영 환경에서 재현하기 어려운 문제를 추적할 수 있도록 로그와 상태를 수집하고, 문제 재현부터 원인 분석, 수정 결과 확인까지 이어지는 검증 경로를 만드는 방식으로 업무를 수행했습니다.

Hi-me / 신규 서비스 개발 / 2025.10~

2025년 10월부터는 HD현대 그룹사 임직원을 대상으로 한 신규 건강관리 서비스 Hi-me의 Android 개발을 담당하고 있습니다. Hi-me는 Android 네이티브 기능과 WebView 기반 화면이 함께 동작하는 하이브리드 서비스로, Google Play 다운로드 2,000건 이상을 기록했습니다. 서비스 개발 과정에서 WebView와 Android 사이의 요청·응답 규격, 상태 코드, 오류 처리 기준을 정리하고, 네이티브 기능 호출이 실패했을 때 Android와 프론트엔드 개발자가 같은 흐름을 기준으로 원인을 확인할 수 있도록 브릿지 구조를 설계했습니다.

WebView 브릿지는 일반적인 HTTP 통신과 달리 요청과 응답을 한눈에 확인할 수 있는 표준 디버깅 도구가 부족했습니다. 호출이 연속으로 발생하거나 IDE를 연결하기 어려운 환경에서는 Logcat에 흩어진 메시지를 직접 찾아 짝지어야 했고, 프론트엔드 개발자와 실패 지점을 공유하기도 어려웠습니다. 이 문제를 해결하기 위해 브릿지 레이어에서 Web-to-App과 App-to-Web 메시지를 함께 수집하는 Dari 디버깅 라이브러리를 개발하고 Hi-me 개발 환경에 적용했습니다. 요청과 응답 매칭, 핸들러 및 상태별 검색, JSON 포매팅, 복사와 공유 기능을 제공해 양쪽 개발자가 브릿지 호출 흐름과 실패 지점을 같은 화면에서 확인할 수 있도록 구성했습니다.

실제 서비스에 적용한 뒤 발견한 인메모리 로그 유실, 단방향 이벤트, 다중 WebView 로그 충돌, 대용량 payload 공유 문제도 개선했습니다. StateFlow를 이용한 즉시 반영과 Room 비동기 저장을 결합하고, 최대 저장 건수와 TTL 기반 정리, 브릿지별 태그, payload 길이 제한을 적용했습니다. Release 빌드에서는 동일한 API를 제공하는 no-op 모듈로 교체해 로그 노출과 불필요한 런타임 동작을 방지했습니다.

카메라 촬영 후 앱으로 돌아왔을 때 사진 업로드가 중단되는 특정 기기 문제도 해결했습니다. Crashlytics에 Fatal 로그가 남지 않는 점을 바탕으로 앱 프로세스 종료와 WebView Renderer 종료를 분리해 추적했고, onRenderProcessGone에서 WebView 버전, 현재 URL, 가용 메모리, didCrash 정보를 Non-Fatal로 수집했습니다. 이를 통해 카메라 실행 중 메모리 압박으로 WebView Renderer가 시스템에 의해 종료되면서 JavaScript 메모리와 callback이 유실되는 상황을 확인했습니다. 앱 전체를 재시작하는 방식 대신 WebView만 재생성·복원하고, 네이티브에서는 촬영 요청과 결과를 ViewModel의 pending state로 보관했습니다. 웹에서는 request id와 진행 상태를 TTL이 있는 localStorage에 저장한 뒤 브릿지가 준비되면 결과를 다시 전달하도록 구성했습니다. 그 결과 Renderer가 종료되더라도 사용자가 진행하던 사진 요청을 복원해 업로드를 완료할 수 있는 흐름을 마련했습니다.

Compose 화면 위에 스플래시나 로딩 오버레이가 표시된 상태에서도 하단 WebView의 JavaScript 클릭 핸들러가 실행되는 문제를 분석했습니다. Modifier.clickable은 Main pass에서 이벤트를 소비하지만 AndroidViewHolder의 pointerInteropFilter가 Initial pass에서 MotionEvent를 WebView에 먼저 전달하는 구조를 확인했습니다. pointerInput과 PointerEventPass.Initial에서 이벤트를 선점해 소비하는 blockTouches modifier를 구현해 오버레이 아래 WebView로 터치가 전달되지 않도록 했으며, Splash·Scrim·Loading 화면에서 공통으로 사용할 수 있는 이벤트 차단 방식으로 정리했습니다.

웹 기반 음악 화면에 백그라운드 재생과 잠금화면·미디어 알림 제어 기능을 추가했습니다. Android WebView의 미디어 세션 제약과 백그라운드 진입 시 재생 중단 문제로 웹 플레이어만으로는 요구사항을 충족하기 어려웠습니다. 전체 화면을 네이티브로 다시 구현하는 대신 웹은 포그라운드 UI를, Android 네이티브는 백그라운드 재생을 담당하도록 역할을 나눴습니다. video.js와 Media3 ExoPlayer·MediaSession 사이에 재생, 일시정지, 탐색, 상태 전달을 위한 양방향 브릿지를 정의하고 양쪽의 재생 상태와 위치를 동기화했습니다. ExoPlayer를 미리 준비하고 전환 과정에서 경과 시간을 보정해 재생 끊김을 줄였으며, 기존 웹 화면을 유지하면서 백그라운드 재생, 잠금화면과 알림 컨트롤, 포그라운드 복귀 시 재생 위치 복원을 지원했습니다.

BLE Glucose Profile과 Blood Pressure Profile을 기반으로 혈당계·혈압계 연동 기능도 개발했습니다. Android OS의 본딩 상태와 앱의 DataStore 연동 정보가 일치하지 않거나, 기기마다 측정값을 전송하고 연결을 종료하는 시점이 달라 데이터 누락과 중복 수신 가능성이 있었습니다. OS의 bondedDevices와 앱의 연동 정보를 교차 검증하고, GATT 명령을 순차 실행하도록 연결 흐름을 구성했습니다. 혈당계는 측정값을 먼저 확보한 뒤 기기 데이터를 삭제하는 Report First, Then Delete 방식으로 처리했고, 혈압계는 lastSyncDate 기반 필터링과 로컬 캐싱을 적용해 이미 반영한 측정값이 다시 저장되지 않도록 했습니다. 연동 해제 시에는 OS 본딩 상태와 앱의 저장 정보를 함께 정리해 연동 상태 불일치 가능성을 낮췄습니다.

건강 데이터 수집에서는 Health Connect를 통한 걸음 수 갱신이 일부 환경에서 원활하지 않은 경우에 대응하기 위해 Samsung Health Data SDK 수집 경로를 추가했습니다. 걸음 수, 심박수, 소모 칼로리를 직접 동기화하고 기존 수집 경로와 함께 사용할 수 있도록 구성했습니다. 반복적인 테스트 배포 작업은 GitHub Actions와 Play Console 내부 테스트 트랙을 연결해 자동화했습니다.

세컨드 윈드·세컨드 닥터 / 유지보수 및 고도화 / 2024.05~

세컨드 윈드와 세컨드 닥터에서는 만성질환자와 암 수술 환자를 위한 건강관리·재활 앱의 유지보수와 기능 고도화를 담당했습니다. 현재 세컨드 윈드와 유방암·전립선암·대장암·위암 대상 세컨드 닥터 4종을 포함해 총 5종을 운영하고 있으며, 서비스 종료 앱을 포함한 전체 출시 앱의 Google Play 누적 다운로드는 13,000건 이상입니다.

운동 영상 재생 기능은 ExoPlayer2에서 Media3로 마이그레이션했습니다. 긴 영상을 모두 내려받은 뒤에만 재생할 수 있어 사용자가 재생 시작까지 기다려야 했던 구조를 구간 단위 다운로드 방식으로 변경했습니다. 전체 파일 다운로드가 끝나지 않았더라도 내려받은 첫 구간부터 재생할 수 있도록 플레이어와 다운로드 흐름을 연결해 재생 시작 대기를 완화했습니다. 또한 TensorFlow Lite와 CameraX를 이용한 어깨 움직임 측정 기능을 개발하고 팔벌림 각도 정확도를 오차범위 ±5도 이내로 개선했습니다. Android OS의 Bluetooth 권한과 동작 정책 변경으로 기존 웨어러블 기기 연동이 중단된 문제에서는 BLE 연동 SDK를 수정하고 AAR로 다시 배포해 기존 앱들이 변경된 SDK를 적용할 수 있도록 했습니다.

브리시드 / 유지보수 및 고도화 / 2024.05~

브리시드에서는 사용자 맞춤 명상 경험을 제공하는 웰니스 앱의 결제, 미디어 재생, 보안 구조를 개선했습니다. Google Play 일회성 인앱 결제를 연동해 유료 콘텐츠 구매 경로를 추가했으며, 명상 음악 플레이어의 Activity와 Service 통신 구조를 Broadcast Receiver에서 Flow 기반 스트림으로 전환했습니다. 재생 상태를 여러 위치에서 개별적으로 주고받던 구조를 하나의 생산·소비 흐름으로 통합해 상태 변경 경로를 명확히 했습니다. 전역 싱글톤으로 관리하던 플레이어와 결제 객체는 Hilt 기반 의존성 주입 구조로 전환했습니다. 객체 생성과 스코프 관리 책임을 DI 컨테이너로 옮겨 컴포넌트 간 결합도를 낮추고, 각 화면과 서비스가 필요한 의존성을 명시적으로 제공받도록 구성했습니다.

KISA 보안취약점 점검에서 지적된 앱 위변조, 루팅, 백그라운드 오버레이 항목에도 대응했습니다. Play Integrity API를 적용해 앱 무결성 확인 경로를 추가하고, 런타임 탐지 로직으로 루팅 및 오버레이 위험 상황을 확인할 수 있도록 구성했습니다.

마이밸런스 / 유지보수 및 고도화 / 2024.05~

마이밸런스에서는 직장인의 건강 습관 형성을 지원하는 건강관리·리워드 앱의 헬스 데이터, 배포, 파일 처리 기능을 개선했습니다. Health Connect를 연동해 걸음 수, 소모 칼로리, 평균 심박수, 수면시간을 수집하는 경로를 통합했습니다. Bamboo 기반 CI/CD 배포 환경을 구축해 빌드 넘버 관리를 자동화하고, 수동 빌드 과정에서 발생하던 충돌 문제를 해결했습니다. 클래스 사진 업로드는 사용자의 갤러리에 파일을 저장한 뒤 업로드하던 방식에서 앱 전용 임시 파일을 생성해 업로드하고 완료 후 제거하는 방식으로 변경했습니다. 이를 통해 업로드를 위해 생성한 파일이 사용자의 미디어 영역에 불필요하게 남지 않도록 했습니다.

기타 업무

이외에도 React Native 기반 사내 심리상담 예약 앱을 유지보수하며 OS 호환성 문제를 수정하고, 생체인증 로그인 정보 자동 완성 기능을 도입했습니다. 네트워크 문제는 요청 조건과 사용자 흐름을 정리해 재현 경로를 확보했습니다. 여러 서비스를 동시에 유지보수하면서 신규 기능 개발, 장애 대응, OS 정책 변화 반영, 보안 점검과 배포 자동화를 수행했습니다. 반복되는 WebView 문제는 Dari와 RoutePeek 같은 재사용 가능한 도구로 발전시켜 문제를 재현하고 공유하기 쉬운 환경을 만들었습니다.
